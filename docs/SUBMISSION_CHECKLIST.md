Useful checks (run from the project root):

```bash
find . -name .env -not -path '*/node_modules/*'
find . -name node_modules -type d -prune
find backend/uploads/documents -type f
find backend/data -type f | head
grep -RIn --exclude-dir=node_modules --exclude-dir=dist --exclude-dir=data \
  -E 'ADMIN_PASSWORD=|JWT_SECRET=' README.md docs 2>/dev/null
```

Expected:

- The only `.env` found is the local `backend/.env`, which must remain untracked.
- `node_modules` directories exist locally but must not appear in the Git index or archive.
- Only `.gitkeep` should be present in `backend/uploads/documents` in the submitted source, unless
  you intentionally include sample files.
- The documentation grep may find variable names and placeholder references, but must not find a
  real administrator password or signing secret.

Remember that test files contain test-only passwords as fixtures. That is different from a deployed
credential, but test files should still be reviewed if the assignment has a strict secret-scanning
rule.

## 7. Git initialisation proposal — approval required

Do **not** run these commands until the repository owner approves them. This project is currently
not a Git repository.

### 7.1 Initialise and inspect

```bash
cd /path/to/mean-admission-system

git init
git branch -M main

git add .
git status --short
```

Before committing, inspect the staged file list. Confirm that it does **not** contain:

- `backend/.env`
- any `node_modules/` directory
- `backend/data/`
- uploaded files other than `.gitkeep`
- `frontend/dist/`
- `frontend/.angular/`
- coverage output or logs

If something sensitive is staged, unstage it:

```bash
git restore --staged <path>
```

Confirm the ignore rules:

```bash
git check-ignore -v backend/.env
git check-ignore -v backend/node_modules
git check-ignore -v backend/data/db
git check-ignore -v frontend/dist
```

These commands should report the matching `.gitignore` rules.

### 7.2 Create the initial commit

```bash
git commit -m "Initial commit: IEM Online Admission System"
```

### 7.3 Create the GitHub repository and push

Create an empty repository on GitHub (do not initialise it with a README, license or `.gitignore` if
you already have local files). Then:

```bash
git remote add origin https://github.com/<your-username>/<your-repository>.git
git branch -M main
git push -u origin main
```

Alternatively, with the GitHub CLI:

```bash
gh repo create <your-repository> --private --source=. --remote=origin --push
```

Choose the visibility and repository name deliberately. Nothing in this project has been uploaded
automatically.

### 7.4 If the assignment requires an archive instead of Git
